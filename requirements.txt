# Building Secure AI Agents: Defense-First Development (Half-day workshop)
#
# Python dependencies:
#   * chromadb  - Lab 4 (RAG hardening) uses a real local Chroma vector database
#                 with real embeddings (Chroma's built-in all-MiniLM-L6-v2,
#                 downloaded once during setup). chromadb uses onnxruntime, not
#                 torch, so it stays CPU-light.
#   * fastmcp   - Lab 3 runs a real Model Context Protocol server.
#   * pyjwt     - Lab 3 mints and verifies scoped JWT access tokens.
#   * opentelemetry-sdk - Lab 5 instruments the agent with real OTel spans.
# Labs 1-2 (guardrails, agent tool controls) use only the Python standard
# library, including the LLM helper (common/llm.py), which talks to Ollama and
# Groq over plain HTTP.
#
# The language model itself is NOT a pip package:
#   * Ollama (llama3.2:3b) is installed and the model pulled by
#     scripts/startup_ollama.sh during Codespace creation (the default).
#   * Groq (openai/gpt-oss-20b / openai/gpt-oss-120b) is a hosted API --
#     set GROQ_API_KEY to use it for the model labs (faster, free tier). Groq
#     also enables the model-based gpt-oss-safeguard safety classifier in Lab 1.

# Version floors/ceilings verified 2026-09-05 against what a fresh Codespace
# actually installs today: chromadb 1.5.9, fastmcp 4.0.3, pyjwt 2.13.0,
# opentelemetry-sdk 1.44.0. Upper bounds keep a major release mid-delivery
# from breaking a lab; re-test and raise them deliberately.
chromadb>=1.5,<2

# Lab 3: real MCP server + scoped JWT auth.
# FastMCP 4.0 went stable 2026-08-31. Lab 3 is verified on 4.0.3: it uses only
# the generic Middleware / on_call_tool / get_http_headers / ToolError surface,
# which survived the 2.x -> 3.x -> 4.x transitions untouched.
fastmcp>=4.0,<5
# 2.13+ rejects empty HMAC keys and binds the header 'alg' to the key during
# verification, so the algorithms=[] allowlist in auth.py cannot be bypassed.
pyjwt>=2.13,<3

# Lab 5: real OpenTelemetry instrumentation
opentelemetry-sdk>=1.20,<2
